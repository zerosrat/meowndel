# 猫色溯源 v2 设计文档

日期：2026-09-06
状态：待评审

## 1. 本次改动的动因

v1（当前 `index.html`）是一个能跑的最小原型：五位点遗传引擎、断言输出、六维输入面板都可用。讨论后确认了六个方向的问题：交互不够有趣、需要区分深浅两种用户、花色只覆盖街猫、输出的可信度需要说清楚、概率缺排序、视觉仍是原型水平。

追加评估后，问题的根源比表面更深，集中在三处：

1. **覆盖率有硬洞**。中国第二常见的街猫花色是白猫，而 W（显性全白）不在模型里，用户根本输入不了。
2. **引擎无测试**。断言的触发条件是算出来的，但句子是手写的；即将从 5 个位点扩到 10 个，没有任何回归保护。
3. **交付形态限制了迭代**。单文件 43KB HTML、字符串拼接 innerHTML、每次点击全量重绘五个面板，与「交互要更有趣」直接冲突。

## 2. 定位调整

v1 的定位是「路人 + 养猫人，不是繁育者」。v2 保持这个定位，但承认一件事：**中国城市里的「养猫人」大多数养的是品种猫**，不覆盖英短就等于放弃了这批人。

调整后的定位：

- 覆盖对象从「街猫」扩展到「街猫 + 主流家养品种猫」
- 仍然不服务繁育者：不做多位点精度、不做导出、不做血统登记
- **两类用户想要的功能方向是相反的**，这一点写进信息架构：
  - 街猫用户要**反推**（爸妈不可知才有意思）
  - 品种猫用户要**正推 + 隐藏携带**（爸妈写在证书上，好奇的是自家猫身上藏着什么）
  - 两个方向对所有品种都保留，但**入口的默认落点不同**

## 3. v1 品种范围

**中华田园猫 + 英国短毛猫 + 美国短毛猫 + 布偶猫。** 暹罗推迟到 v2。

依据（2024-2026 年中国宠物行业数据）：

| 品种 | 占比 | v1 |
|---|---|---|
| 中华田园猫 | ~47% | ✅ |
| 英国短毛猫 | ~20% | ✅ |
| 美国短毛猫 | 第三梯队，上升中 | ✅ |
| 布偶猫 | 约 400 万只，第四 | ✅ |
| 暹罗猫 | 更靠后 | ⏸ v2 |

田园猫内部饲养量前八的花色：橘猫、**白猫**、狸花猫、黑猫、奶牛猫、三花猫、玳瑁猫、山东狮子猫。

决策理由：

- 这四个品种在中国大陆的排名近年高度稳定，合计约占猫总数的 86%
- 田园 + 英短 = 约 67% 覆盖，只需新增 I、Wb 两个位点并扩展 KIT 等位
- 美短带来的 Taqpep 位点同时升级街猫部分（狸花＝鲫鱼纹 vs 美短＝古典纹），一鱼两吃
- 布偶是四者中最贵的一个：需要 C（重点色）、B（巧克力），以及 KIT 再加一个等位基因 `w^g`（手套）。**成本主要落在命名与渲染，不在引擎**（见 4.6–4.8 与第 9 节）
- 暹罗推迟的代价很低：它同样是 `c^s/c^s`，C 位点做完后**遗传部分等于免费**，v2 只差一个 oriental 剪影与品种条目

## 4. 遗传模型 v2

### 4.1 位点表

| 位点 | 基因 | 遗传方式 | 表型 | 状态 |
|---|---|---|---|---|
| O | 橘色 | X 连锁 | 橘 / 非橘 / 玳瑁 | 已有 |
| D | MLPH | 隐性 | 黑→蓝、橘→奶油 | 已有 |
| A | ASIP | 隐性 `aa`＝纯色 | 虎斑开关 | 已有 |
| **KIT** | KIT | **等位系列** `W > W^s > w > w^g` | 全白 / 白斑 / 无白 / 手套 | **扩等位** |
| L | FGF5 | 隐性 | 长毛 | 已有 |
| **I** | 银抑制 | 显性 | 银色、烟色、银渐层 | **新增** |
| **Wb** | CORIN | 隐性，等位系列 | 金渐层 | **新增** |
| **Mc** | Taqpep | `Mc`（鲫鱼纹）显性 > `mc`（古典纹） | 虎斑纹路 | **新增** |
| **C** | TYR | 等位系列 `C > c^s` | 重点色 | **新增** |
| **B** | TYRP1 | 等位系列 `B > b` | 巧克力、丁香 | **新增** |

推迟到 v2：`c^b`（缅甸色）、`b^l`（肉桂色）、Ti（ticked 虎斑）。

### 4.2 KIT 从两等位改为四等位

当前实现把白斑建模为独立的 S 位点，且 `WHITE_S` 把白斑等级硬映射到基因型（「零星白→必然 Ss」「几乎全白→必然 SS」）。这个映射过窄，会产生**假的「不可能」结论**。

改为标准的 KIT 等位系列，显性次序 `W > W^s > w > w^g`：

```
W    显性全白，上位于所有毛色
W^s  白斑，半显性，表达量变异极大
w    无白
w^g  手套（隐性；布偶与伯曼）
```

十种基因型。**手套基因不是独立位点，就在 KIT 上**——这一点已确认。

映射规则改为**多对多**而非一对一：白斑等级 1–4 对应 `{W^sW^s, W^sw, W^sw^g}` 全集，等级只作为**倾向性提示**，不作为排除依据。

能唯一确定基因型的只有两种情况，且**其中一种依赖品种**：

- 「手套」→ 必为 `w^g/w^g`，无条件成立
- 「无白」→ 在田园猫 / 英短 / 美短身上必为 `w/w`（`w^g` 不在这些品种的牌池里）；但在布偶身上可以是 `w/w` 或 `w/w^g`，**无法确定**

第二条正是第 7 节「品种限定等位基因池」为什么是遗传学必要而非 UX 便利的具体例证：同一个表型，在不同品种里的可推断程度不一样。

布偶的三种模式落在同一个位点上：

| 布偶模式 | KIT 基因型 |
|---|---|
| 重点色 | `w/w`、`w/w^g` |
| 手套 | `w^g/w^g` |
| 双色 | `W^s/w`、`W^s/w^g` |
| 高白 / 梵色 | `W^s/W^s` |

这个模型自洽地复现了繁育界观察到的全部经验规律：

- 双色 × 双色 → 1/4 高白、1/2 双色、1/4 重点色
- 手套 × 手套 → 全部手套
- **两只重点色布偶可以生出手套后代**（双方均为 `w/w^g` 时，1/4 概率）——反直觉，是很好的教学点

两个教学点：**全白猫、白斑猫、手套猫是同一个位点的不同等位基因**；且全白是上位的——全白猫底下藏着的花色完全不可知。

### 4.3 Wb（CORIN）的建模依据

上一轮讨论时按旧认知判断「Wb 是多基因、不可建模」。查证后这个判断已过时：

- Abitbol 等人 2022 年在 *Animal Genetics* 定位到 CORIN 基因
- 已知四个等位基因：`wb^SIB`（西伯利亚 Sunshine）、`wb^eSIB`（Extreme Sunshine）、**`wb^BSH`（英短 Copper / 中文「金渐层」）**、`Corin^lc`（孟加拉来源）
- **Sunshine 与 Copper 均为简单隐性**，显性次序 `Wb⁺ > wb^eSIB > wb^SIB`
- FIFe 自 2025 年 1 月起启用 CORIN 代码

v1 只建模 `Wb⁺` 与 `wb^BSH` 两个等位基因（田园猫与英短的牌池），西伯利亚的两个等位基因不在 v1 品种范围内。

**诚实边界**：CORIN 解释了金渐层的有无，但不解释深浅程度，程度仍受 rufousing 多基因影响。界面上金渐层只说「是/否」，不描述深浅。

### 4.4 I（银）的诚实边界

Leslie Lyons 实验室 2024 年 1 月发布银色检测，显性，与 CORIN 是不同座位（所以「银 + 金」可叠加）。

**但该研究发现一小部分银猫身上找不到已知突变。** 模型标注为「基本完整但非全覆盖」，在模型边界章节明写。

### 4.5 Mc（虎斑纹路）的诚实边界

- `Mc`（鲫鱼纹）显性，`mc`（古典纹）隐性 —— 建模
- **点纹（spotted）的机制学界未定论**，普遍认为是修饰基因打断鲫鱼纹 —— **不建模**，界面上不提供「点纹」选项，并在模型边界说明原因

### 4.6 C 位点（重点色）

等位系列 `C > c^b = c^s`。v1 只建模 `C` 与 `c^s`（`c^b` 缅甸色不在品种范围内），三种基因型。`c^s/c^s` ＝ 重点色。

**关键性质：重点色不是一种颜色，是一个「限制表达范围」的开关。** 猫身上完整的花色基因全部保留，只是色素仅在体温较低的四肢、耳、尾与面罩显现。所以存在山猫纹重点色（底下是虎斑）、玳瑁重点色（底下是玳瑁）。

这是继全白之后第二好的教学点，且方向正好相反：**全白是完全遮住，重点色是只露一角。**

### 4.7 B 位点（巧克力）

等位系列 `B > b > b^l`。v1 只建模 `B` 与 `b`（`b^l` 肉桂色不在品种范围内），三种基因型。

`bb` ＝ 巧克力；`bb` 叠加 `dd` ＝ 丁香色。巧克力点与丁香点是布偶的标准色。

### 4.8 布偶白斑：一个现象学模型，标注级别要更高

这是全文档中**认识论状态最弱的一块**，必须单独说明。

- **已确认**：KIT 显性次序 `W > W^s > w`；伯曼的手套基因 `w^g` 为隐性，且位于 KIT
- **未确认**：布偶双色的分子基础。文献表述是「推测可能是 KIT 的又一个等位基因，用以解释现有已知 KIT 变异无法解释的手套与双色的可预测遗传」

也就是说：**繁育界的经验规律高度可预测，但分子机制尚未坐实。** 这与 CORIN 的情况正好相反——那边研究追上了，这边还没有。

处理方式：按 4.2 的四等位模型建模（它自洽地复现全部经验规律），但在界面上**明确标注该结论基于繁育经验规律，而非已确认的分子机制**。标注级别高于其他位点。

## 5. 引擎架构

### 5.1 纯模块化

引擎抽为 `src/genetics/`，纯函数，零 DOM 依赖，可独立测试：

```
src/genetics/
  loci.ts        位点定义、等位基因、显隐关系
  punnett.ts     单位点杂交
  phenotype.ts   基因型 → 表型（含上位关系：W 覆盖一切，I 覆盖 Wb）
  naming.ts      表型 → 中文花色名
  solve.ts       正推 / 反推
  claims.ts      断言生成
  probability.ts 孟德尔比例
```

**每个模块必须能独立回答：它做什么、怎么用、依赖谁。** `naming.ts` 是纯查表，不该知道 `punnett.ts` 的存在。

### 5.2 从边缘集改为联合配对集

当前 `solveParents()` 返回**边缘集**——「哪些父本基因型出现在至少一个合法配对中」。展示层把父、母两行独立渲染，用户可以从两行各挑一只，凑出一个实际不可能的组合（三花的「一橘一非橘」是联合约束，不是边缘约束）。

改为返回**逐位点的合法配对集** `Array<[父基因型, 母基因型]>`。边缘集由配对集派生，而不是反过来。

这同时解锁了两件事：

- 概率排序需要联合配对才算得出来
- 一个具体的交互改进：**点选一只候选妈妈，爸爸行里不兼容的立刻灰掉**。这比静态两行有趣，而且从根上消灭了错位组合

### 5.3 上位关系

新增位点引入了上位（epistasis），必须在 `phenotype.ts` 里显式排序：

1. `W/-` → 全白，覆盖所有其他位点，**包括重点色**（**最强教学点**：全白猫底下的花色完全不可知）
2. `c^s/c^s` → 重点色，把色素限制到四肢、耳、尾与面罩；**底层花色基因完整保留**，在露出的部位照常表达
3. `I/-` → 银色，把 Wb 的金变成银
4. `aa` → 纯色，关掉虎斑纹（**对橘色系无效**，已有逻辑）
5. `wb^BSH/wb^BSH` → 金渐层，需要 `A/-` 才表达

## 6. 概率：诚实的边界在哪

原则不变：**没有可靠的中国街猫等位基因频率，就不编频率。** 但这个原则此前被过度收紧了，实际存在一条干净的分界线。

### 6.1 可以精确计算、零假设的部分

因为表型与基因型一一对应：

- **整个 O 位点**。橘/黑/玳瑁 + 性别 → O 基因型唯一确定。「橘公猫 × 三花母猫 → 女儿一半橘一半三花，儿子一半橘一半黑」是精确的
- **所有隐性表型**。蓝猫必是 `dd`、长毛必是 `ll`、纯色必是 `aa`、金渐层必是 `wb/wb`、古典纹必是 `mc/mc`、巧克力必是 `bb`、**重点色必是 `c^s/c^s`**、**手套布偶必是 `w^g/w^g`**
- 由此得到几条零假设的锐利断言：**重点色 × 重点色 → 100% 重点色**；**手套 × 手套 → 100% 手套**

### 6.2 需要假设、但假设可见的部分

显性表型有歧义（黑猫是 `DD` 还是 `Dd`）。处理方式**不是**编一个频率，而是**把假设变成用户可拨动的控件**：

> 「假设这只黑猫携带稀释基因 →」拨动后实时看比例如何变化

这既保持诚实，又把歧义本身变成教学装置。**这是硬核模式的核心内容。**

### 6.3 反推方向：不给概率，给排序

反推需要群体频率，无解。改为**约束强度排序**。

排序键的精确定义：对每个候选亲本花色，取它在**各位点合法配对集中的出现次数之积**（位点独立，故可相乘），再除以该花色自身兼容的基因型总数做归一。数值大 = 约束更松、更多组合能产生目标幼崽。

**这不是概率**——它等价于「对所有基因型取均匀先验」，而真实群体绝非均匀。因此界面标注必须写「组合数」而非「概率」，并可展开解释两者的区别。

## 7. 品种层：一条架构红线

**品种不是基因输入，不进庞纳特方格。** 引擎保持纯粹的「位点进、位点出」。

品种在系统中只做三件事：

1. **限定等位基因池**。选英短，`wb^BSH` 才可选；选田园猫，CORIN 默认野生型
2. **限定可选花色与控件**。选英短，不出现「点纹」；选美短，纹路默认古典纹；选布偶，KIT 控件从「白色占多少」的五级滑块换成「重点色 / 手套 / 双色 / 高白」四选一——**同一个位点，按品种换说法**
3. **决定剪影体型**。纯展示层

必须在界面上讲清楚的两件事：

- **两只英短生的还是英短，这是繁育登记规则，不是毛色遗传。** 工具不算品种遗传
- **「我家英短 × 楼下狸花会生什么」**：花色可以精确算，品种上是串串，没有登记意义

不划清这条线，用户会以为工具在算品种遗传。

## 8. 信息架构

### 8.1 入口：先选品种

第一步选品种（田园猫 / 英短 / 美短 / 布偶），理由不只是 UX 便利，而是**遗传学上的必要**——CORIN 的等位基因是品种特异的，品种决定了哪些等位基因在牌池里。

品种同时决定**默认落在正推还是反推**：田园猫默认反推（爸妈不可知才有意思），布偶默认正推（从猫舍购猫、亲代写在证书上，好奇的是自家猫藏着什么）。两个方向对所有品种都保留，只是默认落点不同。

### 8.2 深浅两档

**简单模式**（默认）：

- 说人话，不出现基因型符号
- 输出维持三态断言（必然 / 可能 / 不可能）
- 正推给精确比例，但只在零假设的情况下给（见 6.1）

**硬核模式**：

- 展开基因型符号、等位基因记法
- **可拨动的假设控件**（见 6.2）——这是硬核模式的主要价值
- 显示联合配对集、组合数排序
- 显示模型边界与未建模的部分

两档是**每条品种路径内部的开关**，不是两套并行产品。一个养布偶的新手不是「硬核用户」，他只是养的猫不一样。

## 9. 渲染器重做

当前 `catSVG()` 把剪影、底色、纹路、白斑揉在一个函数里。改为分层：

```
剪影(体型原型, 毛长)
  → 底色层 (O × D)
  → 纹路层 (A × Mc × I × Wb)
  → 白斑遮罩 (KIT)
  → 描边
```

v1 体型原型：

| 原型 | 覆盖 | 毛长 |
|---|---|---|
| moderate | 田园猫、美短 | 短 / 长 |
| cobby | 英短 | 短 / 长 |
| ragdoll | 布偶（大体型、半长毛、饰毛尾） | 长 |

共 5 个剪影。cobby-长毛不是为了英国长毛猫（不在 v1 范围），而是因为**两只短毛英短可以生出长毛后代**——这正是 L 位点最好的教学场景，画廊必须画得出来。

底色层新增巧克力与丁香两色。纹路层新增**重点色渲染**：躯干浅、四肢/耳/尾/面罩深，且交界处是渐变而非硬边——**这是整个渲染层里最难画的一种**。

oriental（暹罗）随 v2 品种一起加。

保留 v1 的随机种子设计：同一基因型 roll 出不同白斑位置，科学上正确。

**这是整个项目工作量最大的一块**，是纯手工美术活，远重于引擎。

## 10. 工程化

迁移到 **Vite + React + TypeScript**。

**用 `vite-plugin-singlefile` 把产物内联成单个 HTML 文件**，保留「零部署、双击可开、手机可玩、可当 artifact 分享」的交付形态。开发工程化与单文件交付不矛盾。

测试用 Vitest，覆盖 `src/genetics/` 全部模块。**README 中已验证的四组用例固化为回归测试**，新位点补充对应用例。

## 11. 阶段 1 必须修复的已知缺陷

以下均为已定位的实现缺陷，非设计问题：

## 12. 明确不做

- **品种遗传**。不算「两只猫生的是什么品种」
- **点纹（spotted）**。机制未定论
- **金渐层的深浅程度**。CORIN 解释有无，不解释程度
- **繁育者功能**。多位点精度、导出、血统登记
- **布偶双色的分子机制**。按经验规律建模并明确标注，不假装分子层面已解决（见 4.8）
- **v1 不做**：暹罗（但 C 位点做完后其遗传等于免费，v2 只差 oriental 剪影与品种条目）、`c^b`（缅甸色）、`b^l`（肉桂色）、Ti（ticked）
