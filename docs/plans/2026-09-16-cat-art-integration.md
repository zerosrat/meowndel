## 1. 当前代码能表达什么

依据：`src/genetics/phenotype.ts`、`solve.ts`、`loci.ts`、`catalog.ts`、`children.ts`、`naming.ts`，以及 `src/ui/types.ts`。

| 能力 | 当前实际字段/行为 | 插画接入要求 |
|---|---|---|
| 黑 / 橘 / 玳瑁 | `series` 三选一 | 玳瑁需要黑底+橘块，不能保留三花底图的大块白色 |
| 浓 / 淡 | `dilute` | 同一体型生成蓝、奶油、淡玳瑁等；不根据蓝色猜成英短 |
| 有 / 无虎斑 | `tabby`；橘色在输入端强制有纹 | 不丢弃玳瑁黑色部分的虎斑；没有鲫鱼纹/古典纹区分 |
| 五档白斑 | `white=0..4` | 独立的五档遮罩；全白不等于 `white=4` |
| 短 / 长毛 | `long` | 需要通用长毛底稿；不能拿布偶作为所有长毛结果 |
| 性别 | `UiState.sex`，玳瑁归一化为 F | 名称与图像不依赖性别重复生成；计算仍保留性别 |
| 品种 | 没有个体品种字段 | 不得从父母或毛色自动推定后代品种 |
| 全白 / 银色 / 重点色 | 没有对应字段 | 不能用现有 `white` / `dilute` / `long` 假装实现 |

现有后代输出在长短毛都可能时仍以一张短毛代表图配合顶部说明；必然长毛才输出长毛图与名称前缀。这是当前明确的行为，接入时保留，不擅自拆成双倍卡片。

|---|---|---|

| 田园狸花 | 浓色黑系、有纹、无白、短毛 | 同上；纹路作示意，不新增纹型推断 |
| 田园橘白 | 橘色+中档白斑的候选 | 标定现有遮罩是否符合五档白斑定义 |

| 布偶蓝双色 | 稀释可表达，其余不足 | 同上 |

## 4. 先补什么美术能力

在原画风与轮廓基础上扩展，而不是为每个组合单独生成完整猫图：

1. **底色与纹路**：黑、蓝、橘、奶油、狸花、蓝虎斑；玳瑁/淡玳瑁与各自虎斑版本。
2. **白斑**：从无白到几乎全白五档，遮罩覆盖应递增；白色遮盖下的底色数据仍保留。同一个输入与 seed 稳定，不让重绘随机换脸或换图。
3. **通用长毛**：制作符合当前画风的长毛体型，复用上述颜色规则。英短长毛后代所需体型留在四品种扩展批次，不从母本或 `long=true` 擅自推断。
4. **重点色与银色**：随四品种表达模型接入；不提前将美术预设伪装成计算结果。

白斑验证应测量可着色毛发区域内的遮罩覆盖，并同时检查肉眼辨识。五档表示展示等级，不把遮罩面积当成基因剂量或个体遗传概率。不能仅靠标签叫“约一半”即视作完成标定。

## 5. 数据连接原则

当前接入路径：`CoatSpec + 明确的个体展示上下文 + seed → 插画参数`。

- 名称沿用模型的 `coatName()`；查图使用完整字段键，不以名称或目录下标作为语义。
- 默认采用通用体型，不把蓝/长毛等毛色属性转换成英短/布偶品种。
- 缺素材或不支持的输入使用现有 SVG 作为显式后备，不静默选择最接近的插画。图像加载失败也保留可读名称。
- Canvas 合成放在独立的客户端展示层，不向当前零 DOM 的 `src/genetics` 或 `src/render/catSVG.ts` 注入浏览器依赖。
- 详情弹窗、小卡尺寸与遗传逻辑分开；尺寸暂沿用现有默认，72 px 为未获最终确认的展示提案。

## 6. 实施批次与验收

### A. 当前模型的完整插画覆盖

1. 固定结构化适配契约与不支持输入的返回结果。
2. 补齐颜色、玳瑁、白斑、通用长毛，生成 100 组合的对照页。
3. 验收：字段与名字/插画一致；橘色纹路、白斑递增、长毛轮廓、五官保护和 seed 稳定；全部 100 组合无静默替代。

### B. 主流程接入

1. 依次接入主图、快捷入口、候选卡片和后代卡片/标签。
2. 保留候选配对联动、不可选状态与长短毛可能性文案。
3. 验收：12 个快捷入口、16 个目录项及 1,800 组计算结果；缺素材后备；桌面/手机与深浅主题；`pnpm run check`。

### C. 四品种正式支持

沿用旧 v2 计划的依赖顺序：先观察值/潜在基因型/表达表型及逐个体品种上下文，再核验并实现全白、银色、纹型和重点色等必要能力，然后接入对应品种素材。旧计划中巧克力、金色等更广范围不由这次美术确认自动转成“已实现”或“已缩减”。相关范围需在该批次开工前明确。

关键验收：全白不凭空要求已知底色；颜色不能推定品种；跨品种不套用全局品种过滤；布偶相关未知/经验性结果不能借美术具体化为确定结论。

### D. 动画

静态字段映射和主流程验收后，才做轻量眨眼、呼吸、摆尾；遵循减少动态效果设置。

## 7. 交付体积与资源

当前四品种源图合计 **5,147,144 bytes**，全部探索素材 **22,314,123 bytes**。正式包只纳入运行必需素材，不包含历史试稿。若直接内联 PNG，Base64 会增加体积，不能把全部归档图片放进单文件包。

保留现有单 HTML 交付约定：验证本地 JS/CSS 内联之外，还需增加图片引用与断网可用检查。Git 不存大素材与交付是否单文件是两个独立问题；构建前通过素材清单和校验恢复依赖，运行时不引用本机绝对路径。
