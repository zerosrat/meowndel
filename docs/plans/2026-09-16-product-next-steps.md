# 田园猫接入后的产品迭代

日期：2026-09-16

## 状态与本轮边界

- 已完成：田园猫插画接入主体、父母候选、配偶和后代；覆盖当前模型的 100 种外观，保留 SVG 后备。
- 本轮已授权：提交当前成果、创建 PR、整理后续事项。
- 后续方向：重做页面交互、加入英短；本轮不开始实现。以下是建议顺序和验收要求，不代表页面方案或新品种范围已经定稿。
- 技术验证记录见 [插画接入计划](2026-09-16-cat-art-integration.md)。已有四品种 Demo 只是美术验证，不代表四品种遗传已实现。

## 与总体规划的关系

本计划承接 [v2 总纲](2026-09-06-cat-color-v2-design.md) 的阶段 1 后视觉支线。田园猫接入不代表阶段 2–7 完成；页面交互对应阶段 8 的局部工作。英短的品种上下文与扩展涉及阶段 2、5、6；新增位点仍遵守阶段 2→3、5→6 的依赖，开工时细化执行计划。

## 1. 重做页面交互（建议下一批）

目标：用户能顺畅完成“描述这只猫 → 看父母可能性 → 选择配偶 → 看后代”，并看清花色差异。

实施顺序：
1. 梳理当前入口、选择状态、联动和信息层级，画出桌面与手机的完整流程。
2. 做独立可运行交互样板：主体设置、父母联合筛选、配偶切换、后代结果，以及查看猫图细节的入口。
3. 对比卡片尺寸和信息密度；确认后再替换正式布局。72px 卡片和详情弹窗是候选方案，不作为已定需求。
4. 接入现有计算和插画组件，补交互回归、键盘操作、焦点管理和移动端验证。

验收：选择状态明确、切换后不显示旧图、不可选候选有可理解的说明；放大查看不抢占配对选择操作；长短毛可能性与结果一致；窄屏无横向溢出，深浅背景可读。

开工前需确认：页面结构和核心路径；是否使用详情弹窗及弹窗承载内容。先提供具体样板供确认，不让用户提前决定所有细节。

## 2. 英短接入（页面主流程稳定后）

目标：保留已确认英短轮廓，同时把品种信息与毛色表达分开。

实施顺序：
1. 确定首批范围：哪些英短花色支持计算，哪些仅作展示，哪些明确不支持；蓝色和蓝白可作为优先候选，尚未定稿。
2. 设计每只猫独立的品种上下文，包括主体、父母、配偶、后代及未知/混种状态；不能由蓝色推定英短，不能直接继承母方轮廓。
3. 核验首批花色涉及的模型能力与证据，明确观察值、未知基因型和表达表型之间的连接；必要时细化既有 v2 计划。
4. 复用已确认英短底稿，补齐实际支持组合及后备显示，再接入页面。

验收：同一毛色可对应不同体型；英短与田园猫数据不串用；混种/未知后代不会显示为确定纯种；缺模型能力不能用一张预设图代替推导。

开工前需确认：首批英短花色范围、品种选择入口和跨品种结果表达。金渐层等不能因美术可画就宣称模型支持。

## 3. 后续候选（未排期）

- 美短：品种上下文、纹型及银色能力确认后接入。
- 布偶：重点色、双色及不确定结果的表达明确后接入。
- 全白等模型扩展：不能把几乎全白当作全白，按证据及业务需求单独推进。
- 动画：静态流程稳定后再验证眨眼、呼吸或摆尾，支持减少动态效果。
- 交付优化：拆分主分支遗留实验入口（当前完整单文件约 15.7 MB），优化图片体积和首次渲染速度；补外部素材在新机器/CI 的恢复与备份，继续遵守大素材不进 Git。

这些候选不是本次 PR 的承诺范围。各批次完成时在对应计划记录实现、验证与待确认事项。
