## 1. 3D 猫模型展示与当前 2D 对比（样板完成，主图路线已确认）

目标：通过实际网页效果选择展示路线。本轮结论为主图优先 3D，保留 2D 作为后备；以下验证范围和步骤保留作样板过程记录。

### 验证范围

- 先做一只中华田园短毛猫；优先沿用当前 2D 的可爱程度、脸部特征和体型作为视觉参考。
- 使用真正可转动的 3D 模型在浏览器展示；3D 质感的平面图片或生成器宣传图不能作为模型效果的证明。
- 首轮用同一花色对比（建议橘色虎斑）；通过造型验收后，再以纯黑或黑白验证同一模型换色的成本与一致性。不提前扩展 100 种外观、英短或完整动画。
- 独立对比页面保留当前 2D，采用相近猫体画面占比、背景与默认视角。既看主图，也看父母/后代卡片的实际小尺寸；3D 可旋转检查侧面和背面。

### 实施步骤

1. 回顾已有 3D 实验的实际结果与不足，结合现有 2D 参考明确本次目标。旧 Blender 技术通过不代表其造型已获认可，也不要求重复旧制作方式。
2. 比较可行资产来源：图生 3D、授权现成模型或已有模型修整；按可爱程度、可编辑毛色、许可、费用及无需专业美术技能的可维护性选择一条小样路线。工具和付费服务尚未选定，不因本计划自动购买或订阅。
3. 先检查一个候选模型的正面、三分之四、侧面，以及小尺寸展示。明显不合适就先调整资产来源，避免在不满意的造型上扩大工程。
4. 做可运行的 2D/3D 并排或切换对比，提供旋转、缩放与重置；保留固定默认视角以公平比较。支持模型加载失败和无 WebGL 时返回 2D。
5. 在桌面和手机布局下记录结果，邀请用户评价后做路线决策。真实手机性能未测时明确标记，不能用手机尺寸模拟代替真机验证。

### 验收与决策

| 维度 | 需要观察/记录 |
|---|---|
| 观感 | 可爱程度、田园猫辨识度、正侧面造型、是否优于当前 2D |
| 花色识别 | 主图及小卡尺寸下虎斑/底色是否清楚，换色是否改变脸或体型 |
| 交互价值 | 转动是否帮助理解和观察，还是让基础使用更费力；触屏和按钮是否可用 |
| 成本 | 模型与纹理大小、首屏加载、旋转流畅度、制作与花色扩展所需人工成本 |
| 工程边界 | 资产许可与恢复说明、降级、资源释放；独立样板不继续拖大正式主页面 |

已确认选择：主图优先 3D，2D 作为 3D 搞不定时的备选。该选择不等于已有全部花色的 3D 资产，也不等于小卡片已选定表现形式。

与历史计划关系：[旧 3D 试验](2026-09-07-single-cat-3d-spike.md) 保留作复盘证据；本轮的下一步顺序与对比范围以本节为准。大模型、纹理和源文件继续存于 Git 外，提交恢复清单及代码。

## 1.1 主图接入（下一批，待实施）

已确认方向：主体猫优先 3D。2D 作为可继续使用的后备方案，不再平行扩展两套新美术。

实施顺序：
1. 审核四套固定资产能够准确表达的外观范围，建立明确匹配规则。按毛色、纹型、白斑与毛长等表型选资产，不按名称模糊匹配；短毛固定贴图不能代替长毛、稀释色或不匹配白斑的结果。
2. 抽出统一主图入口：准确匹配且美术已认可时显示 3D；缺匹配素材、素材不达标、加载失败或 WebGL 不可用时显示当前对应的 2D。加载中也保留当前猫的 2D，占位不能沿用上一只猫。
3. 复用按需绘制、视角按钮和资源释放；限制同时存在的可交互 3D 场景数量。小卡片先沿用现有实现，待实际页面样板比较后再定。
4. 落实素材恢复与打包：源文件继续放 Git 外；正式产物仍须满足单个 `dist/index.html` 离线打开及不新增运行时网络依赖。评估内嵌资源后的体积，不能直接把开发页的外部 GLB 路径当作正式接入。
5. 验证准确匹配/不匹配、快速换猫、加载失败、无 WebGL 和卸载释放；遗传计算与冻结基线不变。补真机性能评估，明确未覆盖的设备范围。

验收：有合适 3D 就显示 3D，无合适 3D 就显示正确 2D；不会为了维持 3D 展示而画错猫。该节是下一批实施步骤，不代表正式页面已经替换。

## 2. 重做页面交互（展示路线确定后）

目标：用户能顺畅完成“描述这只猫 → 看父母可能性 → 选择配偶 → 看后代”，并看清花色差异。

实施顺序：
1. 梳理当前入口、选择状态、联动和信息层级，画出桌面与手机的完整流程。
2. 做独立可运行交互样板：主体设置、父母联合筛选、配偶切换、后代结果，以及查看猫图细节的入口。
3. 对比卡片尺寸和信息密度；确认后再替换正式布局。72px 卡片和详情弹窗是候选方案，不作为已定需求。
4. 接入现有计算和插画组件，补交互回归、键盘操作、焦点管理和移动端验证。

验收：选择状态明确、切换后不显示旧图、不可选候选有可理解的说明；放大查看不抢占配对选择操作；长短毛可能性与结果一致；窄屏无横向溢出，深浅背景可读。

开工前需确认：页面结构和核心路径；是否使用详情弹窗及弹窗承载内容。先提供具体样板供确认，不让用户提前决定所有细节。

## 3. 英短接入（展示路线和页面主流程稳定后）

目标：保留已确认英短轮廓，同时把品种信息与毛色表达分开。

实施顺序：
1. 确定首批范围：哪些英短花色支持计算，哪些仅作展示，哪些明确不支持；蓝色和蓝白可作为优先候选，尚未定稿。
2. 设计每只猫独立的品种上下文，包括主体、父母、配偶、后代及未知/混种状态；不能由蓝色推定英短，不能直接继承母方轮廓。
3. 核验首批花色涉及的模型能力与证据，明确观察值、未知基因型和表达表型之间的连接；必要时细化既有 v2 计划。
4. 按选定展示路线接入英短：2D 复用已确认底稿；3D 或混合方案先验证对应模型，不能把 2D 轮廓确认等同于 3D 模型确认。补齐实际支持组合及后备显示，再接入页面。

验收：同一毛色可对应不同体型；英短与田园猫数据不串用；混种/未知后代不会显示为确定纯种；缺模型能力不能用一张预设图代替推导。

开工前需确认：首批英短花色范围、品种选择入口和跨品种结果表达。金渐层等不能因美术可画就宣称模型支持。

## 4. 后续候选（未排期）

- 美短：品种上下文、纹型及银色能力确认后接入。
- 布偶：重点色、双色及不确定结果的表达明确后接入。
- 全白等模型扩展：不能把几乎全白当作全白，按证据及业务需求单独推进。
- 动画：静态流程稳定后再验证眨眼、呼吸或摆尾，支持减少动态效果。
- 交付优化：拆分主分支遗留实验入口（当前完整单文件约 15.7 MB），优化图片体积和首次渲染速度；补外部素材在新机器/CI 的恢复与备份，继续遵守大素材不进 Git。

这些候选不是本次 PR 的承诺范围。各批次完成时在对应计划记录实现、验证与待确认事项。
